# รีวิว UI ของ SuperK Manga Translator

วันที่: 2026-09-05
ขอบเขต: `src/app/page.tsx` และ components ของ workspace, editing, cleaning

## ภาพรวม

ควรปรับความชัดเจนและความต่อเนื่องของการใช้งานก่อนเปลี่ยนรูปลักษณ์ โทนมืดและพื้นที่นำเข้าที่เรียบเหมาะกับงานมังงะอยู่แล้ว ปัญหาสำคัญคือการเข้าถึงตั้งค่าระหว่างทำงาน การตอบสนองของปุ่มหลัก และสถานะนำเข้า

ตรวจหน้าเริ่มต้นที่มีข้อเสนอคืนค่า session และหน้าตั้งค่าจริงบน desktop 1280×720 ส่วน workspace หลังนำเข้าใช้การไล่โค้ด ไม่ได้เปิด session เดิมหรือเรียก AI จึงยังไม่ใช่การทดสอบ workflow ทั้งหมดบน browser

## รูปลักษณ์และผลสแกน

หน้าเริ่มต้นดูเป็นเครื่องมือที่เน้นเนื้อหา ไม่มีเหตุผลต้องเปลี่ยนธีมหรือเพิ่มสีสัน ขณะเดียวกัน toolbar แบบลอยซึ่งใช้ทั้ง border, shadow และ blur หลายจุดทำให้ workspace ซับซ้อนกว่าหลักการออกแบบเดิม

Detector พบ 1 warning กฎ broken-image ที่ `src/app/page.tsx:1338` แต่ตรวจแล้วเป็น false positive: รูป offscreen ถูกซ่อนและรับ src ในกระบวนการส่งออก จึงไม่มีปัญหาภาพเสียที่แสดงให้ผู้ใช้จากผลสแกนนี้ ทั้งนี้ detector ไม่ได้พิสูจน์ว่า UI ไม่มีปัญหาอื่น

## สิ่งที่ควรรักษา

- หน้าเริ่มต้นมีงานหลักเดียว พร้อมระบุประเภทไฟล์ที่รองรับ
- การเสนอคืนค่างานเดิมพร้อมจำนวนหน้าช่วยให้กลับมาทำงานต่อได้
- Zoom, focus mode, glossary และ batch translation รองรับการทำงานต่อเนื่อง

## ข้อเสนอเรียงตามความสำคัญ

### 1. [P1] คงปุ่มตั้งค่าไว้หลังนำเข้าภาพ

หลักฐาน: `src/app/page.tsx:909` แสดงปุ่มตั้งค่าเฉพาะ desktop branch ที่ pages.length เป็นศูนย์ หลังนำเข้าไม่มี trigger ใน desktop header เหลือเฉพาะเมนู mobile ที่บรรทัด 1153

ผลกระทบ: เปลี่ยนฟอนต์ ภาษา glossary หรือ API ระหว่างทำงานไม่ได้จาก UI desktop ปกติ

แก้ขั้นต่ำ: วางปุ่มตั้งค่าถาวรใน header ทั้งก่อนและหลังนำเข้า ไม่ต้องจัด layout ใหม่ทั้งหมด

คำสั่งสำหรับงานต่อ: `$impeccable shape`

### 2. [P1] เชื่อมปุ่มส่งออกหลักให้เปิดเมนูจริง

หลักฐาน: `src/app/page.tsx:304` เรียก exportTriggerRef.current?.click() แต่ WorkspaceExportMenu ที่บรรทัด 1012 ไม่ได้รับ triggerRef แม้ component รองรับอยู่แล้วใน `components/workspace/WorkspaceExportMenu.tsx:18`

ผลกระทบ: ปุ่มหลักเมื่อถึงสถานะส่งออกไม่มีผล ผู้ใช้ต้องเลือกเมนูส่งออกข้างเคียงเอง

แก้ขั้นต่ำ: ส่ง ref ให้ component หรือใช้สถานะเปิดเมนูร่วมกัน แล้วตรวจเส้นทางตรวจงาน → ส่งออกด้วยเมาส์และคีย์บอร์ด

คำสั่งสำหรับงานต่อ: `$impeccable harden`

### 3. [P1] แสดงสถานะระหว่างนำเข้าและข้อผิดพลาด

หลักฐาน: processFiles ใน `src/app/page.tsx:747` สะสมภาพก่อน setPages ส่วน ZIP/PDF catch ที่บรรทัด 768 และ 800 แจ้งเฉพาะ console

ผลกระทบ: ไฟล์ใหญ่ดูเหมือนไม่ตอบสนอง ไฟล์เสียดูเหมือนกดไม่ติด ผู้ใช้อาจส่งไฟล์ซ้ำ

แก้ขั้นต่ำ: แสดงชื่อไฟล์และจำนวนหน้าที่เตรียมแล้ว ป้องกันการนำเข้าซ้ำระหว่างงาน และแสดงข้อผิดพลาดรายไฟล์พร้อมลองใหม่ โดยรักษาหน้าที่นำเข้าสำเร็จ

คำสั่งสำหรับงานต่อ: `$impeccable harden`

### 4. [P1] ทำให้การนำเข้าและตั้งค่าใช้คีย์บอร์ดได้ครบ

หลักฐานจริงจาก accessibility tree: Browse Files มีเพียงข้อความ ไม่มี control ให้ focus; `src/app/page.tsx:1394` ใช้ label ที่ focus ไม่ได้ และ input เป็น hidden บรรทัด 1396 ช่องตั้งค่าหลายช่องไม่มีชื่อที่เชื่อมกับ control เช่น `components/workspace/SettingsModal.tsx:132`, 154, 175, 190, 208, 263, 270, 291, 313

ผลกระทบ: ผู้ใช้คีย์บอร์ดเริ่มนำเข้าไม่ได้ และ screen reader ไม่รู้ว่าช่องตั้งค่าแต่ละช่องคืออะไร

แก้ขั้นต่ำ: ใช้ปุ่มจริงเปิด file input หรือ input ที่ซ่อนเฉพาะทางสายตา เชื่อม label กับ id และคืน focus ไปปุ่มตั้งค่าเมื่อปิด dialog

คำสั่งสำหรับงานต่อ: `$impeccable harden`

### 5. [P2] ลดเครื่องมือซ้ำและแยกงานแก้ไขขั้นสูง

หลักฐาน: `components/cleaning/CleaningToolbar.tsx:61` มีปุ่มคลีนสีเด่น พร้อม Original/Clean/Translated/Mask และแก้ Mask ขณะที่ `components/workspace/WorkspaceAdvancedTools.tsx:36` มีคลีนและแก้ Mask ซ้ำ ส่วน `src/app/page.tsx:1284` แสดง toolbar นี้ตลอดเมื่อมีหน้า

ผลกระทบ: ผู้ใช้ต้องตัดสินใจว่าจะคลีนเองหรือใช้ปุ่มแปลหลัก และพื้นที่ควบคุมแย่งความสนใจจากภาพ

ข้อเสนอ: ให้ปุ่มตามขั้นตอนหลักเด่นที่สุด คงการเปรียบเทียบต้นฉบับ/คำแปลไว้ และรวม Clean/Mask ไว้ในโหมดแก้พื้นภาพ สำหรับ settings แบ่งกลุ่ม ภาษาและคำศัพท์ / รูปแบบข้อความ / การเชื่อมต่อและขั้นสูง

คำสั่งสำหรับงานต่อ: `$impeccable distill`

## ภาระในการตัดสินใจและความรู้สึกระหว่างใช้งาน

หน้าเริ่มต้นมีภาระต่ำ หลังนำเข้ามีตัวเลือกซ้ำ ศัพท์เทคนิค และเครื่องมือที่ซ่อนอยู่ จุดที่มีตัวเลือกหลายอย่างคือ toolbar คลีนประมาณ 6 controls เมนู export 5 formats และรายการ model 8 ตัวเลือก จำนวนอย่างเดียวไม่ใช่ข้อผิดพลาด แต่ควรจัดกลุ่มตามงานที่ผู้ใช้ต้องการทำ

จุดเริ่มต้นสงบและการคืนงานเดิมช่วยให้มั่นใจ ช่วงนำเข้าไม่มี feedback ทำให้ไม่แน่ใจว่าระบบรับไฟล์แล้วหรือไม่ และปุ่มส่งออกหลักที่ไม่ตอบสนองทำให้ขั้นตอนจบสะดุด

## มุมมองผู้ใช้

- ผู้เริ่มใช้: ไทย/อังกฤษปะปน และคำว่า Mask หรือ Font Size Multiplier ต้องตีความเพิ่ม
- ผู้ทำงานหลายหน้า: ตั้งค่าหายระหว่างทำงาน และแปลทั้งเล่มอยู่ในเครื่องมือขั้นสูง
- ผู้ใช้คีย์บอร์ดหรือ screen reader: เปิดไฟล์ไม่ได้จาก Tab และช่องตั้งค่าหลายช่องไม่มีชื่อกำกับ

## ข้อสังเกตรอง

- ใช้ภาษาไทยกับ action หลักให้สม่ำเสมอ เช่น เลือกไฟล์ / ต้นฉบับ / ภาพคลีน / คำแปล
- เพิ่มลูกศร dropdown ใน select ที่ใช้ appearance-none เพื่อให้รู้ว่ากดเลือกได้
- เพิ่มทางเข้า “คีย์ลัด” ที่มองเห็น แทนการต้องรู้ก่อนว่ากด ? ได้
- ให้การลบหน้ามี Undo ที่เรียกคืนได้โดยไม่รบกวนด้วย confirmation ทุกครั้ง
- ลด blur และเงาของ floating toolbar โดยยังรักษาการแยกพื้นผิวออกจากภาพ
- ยังไม่ได้วัด contrast เชิงตัวเลข และไม่ได้ตรวจ responsive/mobile จริง จึงไม่สรุปว่าผ่านหรือไม่ผ่าน

## ประเด็นตัดสินใจสำหรับงานต่อ

- ควรให้ workflow ปกติเป็น นำเข้า → แปล → ตรวจแก้ → ส่งออก และเปิดเครื่องมือคลีนละเอียดเฉพาะเมื่อแก้ปัญหาหรือไม่?
- เมื่อนำเข้าหลายหน้า ควรให้แปลทั้งเล่มค้นพบได้ง่ายกว่าเมนูขั้นสูงหรือไม่?
- ข้อมูลสถานะงานที่ต้องเห็นตลอดควรมีอะไรบ้าง: การบันทึก หน้าที่กำลังทำ และความพร้อมส่งออก?

ข้อเสนอเริ่มงาน: แก้ข้อ 1–4 ก่อน แล้วค่อยลดเครื่องมือซ้ำในข้อ 5 โดยรักษาโทนและ canvas เดิม
