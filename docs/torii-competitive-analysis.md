# Torii คู่แข่งตรง: วิเคราะห์ระบบเทียบกับ SuperK

วันที่เก็บข้อมูล: 2026-11-11 ที่มาหลักคือเว็บ toriitranslate.com และโค้ดจริงสองชิ้นคือ `translate.js` (เว็บแอป 1.8MB) และส่วนขยาย Firefox XPI v2.24.1 ที่ดาวน์โหลดและแตกดู ข้อความทุกข้อในเอกสารนี้มีป้ายแหล่งที่มากำกับ ข้อมูลที่อนุมานจะเขียนกำกับชัดเจน

## ภาพรวม Torii

Torii เป็นแพลตฟอร์มแปลมังงะด้วย AI ทำโดยนักพัฒนาคนเดียว อัปเดตเกือบทุกสัปดาห์ มีผู้ใช้ 20,000+ คน คะแนน 4.3 บน Chrome Web Store และผู้ใช้กระตือรือร้น 2,798 คนต่อวันบน Firefox (อ้าง: หน้าแรก + AMO API 2026-11-11)

รูปแบบธุรกิจคือเครดิตแบบซื้อขาด ไม่มีสมาชิกรายเดือน

| แพ็กเครดิต | ราคา | ต่อ 1,000 เครดิต |
|---|---|---|
| 2,500 | $5.99 | $2.40 |
| 6,000 (ยอดนิยม) | $12.99 | $2.16 |
| 15,000 | $29.99 | $1.92 |

กติกาคร่าว ๆ คือ 1 เครดิต แปลได้ 1 หน้ากับโมเดลเร็ว ใช้ key ตัวเอง (BYOK) โดนแค่ค่าสแกน 1 เครดิต แปลซ้ำภาพเดิมภายใน 1 สัปดาห์ฟรีเพราะแคชอยู่บนเครื่องผู้ใช้ (อ้าง: หน้า pricing)

## อะไรคืออะไร

หมวดนี้อธิบายศัพท์ที่ใช้ตลอดเอกสาร ให้ความหมายตรง ๆ ไม่ต้องมีพื้นฐานมาก่อน

### ขั้นตอนการแปลมังงะหนึ่งรอบมีอะไรบ้าง

- **OCR** คือการอ่านตัวอักษรจากรูปให้กลายเป็นข้อความ ย่อจาก Optical Character Recognition
- **Vision LLM** คือ AI ที่มองภาพและอ่านภาษาได้พร้อมกัน เช่น Gemini ใช้ทำ OCR ก็ได้ ใช้แปลก็ได้ ข้อดีคือเข้าใจบริบท ข้อเสียคือแพงกว่าและอ่านพลาดได้ง่ายกว่า OCR เฉพาะทาง
- **Inpainting** คือการลบตัวอักษรเดิมออกจากภาพแล้วเติมพื้นที่ว่างให้กลับไปดูเหมือนภาพเดิม
- **Mask** คือภาพประกอบสีดำสีขาวที่บอกว่า "จุดนี้ต้องลบ" เป็นขาว จุดอื่นปล่อยไว้ คุณภาพ mask กำหนดคุณภาพของ inpainting โดยตรง
- **Typesetting** คือการจัดวางคำแปลลงในบับเบิล เลือกขนาดฟอนต์ บังคับบรรทัด หมุน และจัดกึ่งกลาง
- **Screentone** คือลายจุดหรือลายเฉดที่พิมพ์ซ้ำ ๆ ในมังงะขาวดำ ใช้แทนเงาและสี ถ้าลบผิดวิธีรอยจะไม่กลับมาตรงลายเดิม
- **SFX** คือตัวอักษรเสียงเอฟเฟกต์ใหญ่ ๆ เช่น "โก๊ะ" หรือ "BAM" ที่วาดกินพื้นที่ศิลป์ ลบแล้วมักทำให้ภาพพัง
- **Context ข้ามหน้า** คือการส่งเรื่องย่อ ชื่อตัวละคร และคำศัพท์ของหน้าก่อน ๆ ไปให้ AI หน้าถัดไปรู้ด้วย เพื่อให้ชื่อแปลตรงกันทั้งเล่ม
- **Glossary** คือคลังคำที่บังคับแปล เช่น "อาจารย์" ต้องออกเสียงอย่างนั้น ชื่อตัวละครห้ามเปลี่ยน

### ระบบฝั่ง SuperK (โปรเจกต์ของเรา)

- **CTD (Comic Text Detector)** คือโมเดลหาบับเบิลและข้อความของเรา รันในเครื่องผ่าน ONNX ที่ `ocr-service/app/detector.py`
- **LaMa** คือโมเดล inpainting คุณภาพสูงที่เราใช้เป็นตัวหลัก ไฟล์อยู่ที่ `ocr-service/app/cleaners/lama_large.py`
- **Tier router** คือตัวตัดสินว่าภาพนี้ควรลบด้วยวิธีไหน ระหว่าง LaMa, AOT (เติมสีเรียบ), หรือเติมลาย screentone ใหม่
- **Verifier** คือด่านตรวจหลังลบ สแกนหาเศษตัวอักษรที่เหลือ ถ้าเจอจะสั่งลบซ้ำให้สะอาด
- **Ollama** คือโปรแกรมรันโมเดล AI ในเครื่องตัวเองโดยไม่ต้องจ่ายค่า cloud เราใช้เป็น Local engine
- **Descrambler** คือเครื่องมือถอดภาพสแกนที่เว็บอ่านแหล่งนึงพรากเป็นชิ้นสับระเบียบ ให้ประกอบกลับมาอ่านได้ อยู่ที่ `lib/extension/descrambler.ts`
- **Publish-back** คือการส่งงานที่แก้ในเว็บแอป ย้อนกลับไปแสดงในส่วนขยายที่หน้าเว็บที่อ่านอยู่

### ระบบฝั่ง Torii

- **Firebase / Firestore** คือบริการของ Google ที่ให้ระบบบัญชี ฐานข้อมูล และสถิติแบบสำเร็จรูป เขาใช้เก็บบัญชีและเครดิตโดยไม่ต้องเขียนเซิร์ฟเวอร์ส่วนนั้นเอง
- **BYOK** ย่อจาก Bring Your Own Key คือผู้ใช้เอา API key ที่เสียค่าจองตัวเองมาใส่ ค่า AI จึงไม่เข้าบิลของ Torii
- **Chunk** คือการหั่นภาพหรือไฟล์ใหญ่เป็นชิ้นเล็กส่งทีละชิ้น ใช้กับเว็บตูนยาวหลายหมื่นพิกเซล
- **Telemetry** คือการส่งสถิติการใช้งานกลับไปหาผู้ทำ เช่น ใช้ฟีเจอร์ไหน ผิดพลาดตรงไหน
- **Hook mode** คือการดักข้อความจากความจำของโปรแกรมเกมโดยตรง ใช้ใน Visual Novel Translator

### ศัพท์แพลตฟอร์ม

- **MV3 (Manifest V3)** คือมาตรฐานโครงสร้างส่วนขยายรุ่นปัจจุบันของ Chrome
- **PWA** คือเว็บแอปที่ติดตั้งลงหน้าจอได้เหมือนแอปจริง ของเรามีโครงไว้แต่ปิดอยู่ที่ `next.config.ts`
- **XPI / CRX** คือไฟล์แพ็กเกจส่วนขยายของ Firefox และ Chrome ตามลำดับ

## สถาปัตยกรรมของ Torii

โครงหลักคือ "เครื่องผู้ใช้บาง เซิร์ฟเวอร์หนัก"

- งานอัจฉริยะทั้งหมดอยู่หลัง `api.toriitranslate.com` เส้นทางหลักคือ `/v2/upload` (แปลเต็มกระบวนการ) และมี `/api/inpaint`, `/api/colorize`, `/api/reporting`, `/api/byok/encrypt` (วัดจาก grep ใน `translate.js` และ `content.js`)
- มีโฮสต์ `direct-api.toriitranslate.com` แยกไว้ น่าจะสำหรับเส้นทาง BYOK (ป้าย: อนุมานจากชื่อและจุดอ้างในโค้ด)
- บัญชีและเครดิตใช้ Firebase ครบชุด: Auth, Firestore, Analytics (วัดจาก script preload ใน HTML ทุกหน้า)
- **พรอมต์แปลถูกซ่อนฝั่งเซิร์ฟเวอร์** ค้นหา "You are" ใน bundle ทั้งเว็บและส่วนขยายไม่พบสักจุด ต่างจาก SuperK ที่พรอมต์อยู่ใน `src/app/api/translate/handler.ts` อ่านได้หมด
- **ส่วนขยายไม่มี ML บนเครื่องเลย** ค้น tesseract, manga-ocr, onnx, wasm ได้ศูนย์ทุกตัว WebGL ใน `content.js` ทำแค่ inpaint/วางตัวอักษรฝั่งเครื่อง (247 จุดอ้าง inpaint, 15 จุด WebGL)
- สตริปยาวถูกส่งแบบแบ่งชิ้นด้วย `CHUNK_SIZE = 104857` ไบต์ (ราว 1MB) และ `sendChunkedMessage` (วัดจาก `content.js`)
- คีย์ BYOK ของผู้ใช้ถูกเข้ารหัสเก็บฝั่งเขาผ่าน `/api/byok/encrypt` แลกความสะดวกข้ามอุปกรณ์ ขณะที่คีย์ของ SuperK อยู่บนเครื่องผู้ใช้
- รูปทั้งหมดเก็บบนเครื่องผู้ใช้ตามการเปลี่ยนแปลง 26/01/26 (อ้าง: หน้า updates)

## ผลิตภัณฑ์และแพลตฟอร์ม

ครอบครัวผลิตภัณฑ์มี 5 หน้าแชร์บัญชีและเครดิตเดียวกัน (อ้าง: หน้า products และลิงก์ในไซต์)

1. ส่วนขยายเบราว์เซอร์: Chrome, Edge, Brave, Opera, Firefox รวม Android, Safari บน Mac, iPad, iPhone
2. เว็บแอปแปลภาพ (`/image`): อัปโหลดรูป, ZIP, PDF แปลเป็นชุด มีโฟลเดอร์และไฟล์โปรเจกต์
3. แปลข้อความ (`/text`)
4. แปลไลต์โนเวล/เอกสาร (`/document`)
5. Visual Novel Translator: แอปเดสก์ท็อป Windows 10/11 v1.0.1 อ่านข้อความจาก memory เกม (hook mode รองรับเอนจินญี่ปุ่นและ Ren'Py) มี screen OCR เป็น fallback วางคำแปลบนภาพเกมด้วย AI inpaint แจกผ่าน GitHub releases ขนาดราว 100MB ยังไม่มีใบรับรองดิจิทัล (อ้าง: หน้า /visualnovel)

มี API สาธารณะขายให้นักพัฒนาด้วย (`/api`): OCR 1 เครดิต, inpaint 0.02, typeset 0.02 ถึง 0.1, colorize 1 ถึง 46 ตามโมเดล, translate ขั้นต่ำ 1 จำกัด 1 คำขอ/วินาที พร้อม queue 100 คำขอ ไฟล์ใหญ่สุด 50MB และ 100,000px (อ้าง: หน้า /api)

## ระบบราคาต่อโมเดล

เว็บแอปเก็บราคา API ต่อล้านโทเคนของทุกโมเดลไว้ใน client และคิดเครดิตจากต้นทุนจริง ตัวอย่างจากโค้ด:

```
{ value: "gemini-3.1-flash-lite", text: "Gemini 3.1 Flash Lite", provider: "google", cost: 1, inputPerM: 0.25, outputPerM: 1.50 }
```

โมเดล default คือ Gemini 3.1 Flash Lite รายชื่อในโค้ดรวม gpt-6.1-sol, gpt-6-luna, grok-4.20, gpt-image-2, grok-imagine-image, gemini-nano-banana-2.1 (วัดจาก grep ใน `translate.js`)

colorize มี 5 โมเดล: Torii Local 1 เครดิต, Muse 12, GPT Image 2 16, Grok Imagine 25, Nano Banana 2.1 46 (อ้าง: หน้า /api และ updates 07/11/26)

เขาเคยตัด Gemini 3 Pro ออกเพราะต้นทุนคาดเดาไม่ได้ตาม changelog 24/02/26 ซึ่งยืนยันว่าการทำ model routing ที่มี fallback อย่างที่ SuperK ทำคือทิศทางที่ถูก

## สิ่งที่ SuperK ควรยืม เรียงตามคุ้มค่า

1. สตริปยาวแบบ chunk เป็นช่องว่างใหญ่สุด ตลาดเว็บตูนใหญ่กว่ามังงะหน้าเดี่ยว เรามี job queue อยู่แล้ว (`ocr-service/app/jobs.py`) จึงต่อยอดได้
2. ยิง context ข้ามหน้าจริง ฟิลด์ `context` รออยู่ใน contract แต่ไม่มีตัวเติม เขาขายฟีเจอร์นี้เป็นจุดต่างหลัก พร้อม glossary ต่อโปรเจกต์
3. ตัวอักษรเป้าหมายแนวตั้ง ปลดล็อกตลาดผลลัพธ์เป็นญี่ปุ่น/จีน/เกาหลี เรามี `lib/typeset/BubbleTypesetEngine.ts` แล้ว ขาด renderer แนวตั้ง
4. compare แบบสไลด์ด้านข้าง เขามี drag-compare เราสลับเลเยอร์อย่างเดียว ของเล็กแต่สร้างความประทับใจ
5. auto-translate ตอนสกรอลล์ + ประวัติในส่วนขยาย ทำให้ส่วนขยายเป็นช่องทางดึงผู้ใช้เข้าเว็บแอป
6. ถ้าเปิดเก็บเงินวันหนึ่ง ให้ลอกโครงตาราง `cost/inputPerM/outputPerM` ต่อโมเดล

## บทสรุปเชิงกลยุทธ์

Torii คือสถาปัตยกรรมเครื่องบางที่ขายความสะดวกข้ามอุปกรณ์ SuperK คือสถาปัตยกรรมเครื่องหนักที่ขายการควบคุม ความโปร่งใส และความฟรี สองตำแหน่งไม่ชนกันโดยตรง แต่ฟีเจอร์ที่เขามีแล้วผู้ใช้คาดหวังคือสตริปยาว, context ข้ามหน้า และ colorize เราควรมีไม่ให้ขาด ขณะที่จุดขายที่ยังเป็นของเราคนเดียวคือ pipeline ทั้งหมดรันในเครื่องผู้ใช้ได้โดยไม่ต้องจ่ายเครดิต
