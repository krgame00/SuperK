# แบบระบบตรวจความอ่านง่ายก่อนส่งออก

- วันที่: 2026-09-27
- สถานะ: อนุมัติแบบและความเข้าใจร่วมกันเมื่อ 2026-09-27; พร้อมเขียนแผนลงมือทำ
- ขอบเขต: รายงานก่อนส่งออกของเวิร์กสเปซ

## เป้าหมาย

ก่อนส่งออก ผู้ใช้เห็นว่าข้อความจุดใดล้นกรอบ เล็กเกินไป หรืออาจกลืนกับพื้นหลัง กดจากรายงานเพื่อไปดูจุดนั้นบนหน้ามังงะ แล้วแก้ด้วยเครื่องมือเดิมได้ การตรวจเป็นคำเตือนเท่านั้น ผู้ใช้ส่งออกได้เสมอ

## สภาพปัจจุบัน

`ExportReportModal` สรุปสถานะการแปล อักษรต่างภาษา กรอบผิดปกติ และบริเวณคลีนที่รอตรวจเป็นรายหน้า `fitTextForBubble` ส่งค่า `fits` และขนาดฟอนต์ที่ใช้เรนเดอร์ `resolveBubbleTextStyle` ตัดสินสไตล์และความอ่านง่ายของสีอัตโนมัติอยู่แล้ว โดยการตั้งค่าสีด้วยมือมีสิทธิ์เหนือสไตล์อัตโนมัติ ระบบใหม่นำผลของเส้นทางเหล่านี้มาแสดงเป็นคำเตือนระดับจุดข้อความ ไม่สร้างตัวเรนเดอร์หรือกฎแก้สีแยกอีกชุด

## แนวทางที่เลือก

1. ตรวจรูปทรงและขนาดตัวอักษรจากข้อมูลจัดวางที่ใช้ส่งออกจริง และตรวจความต่างของสีจากสไตล์ที่ใช้เรนเดอร์เทียบกับพื้นหลังบริเวณข้อความ
2. แสดงคำเตือนแยกเป็น `ข้อความล้นกรอบ`, `ตัวอักษรเล็ก`, `สีกลืนกับพื้นหลัง` พร้อมหน้า จุดข้อความ และเหตุผลที่อ่านเข้าใจได้ จุดเดียวมีได้หลายคำเตือน
3. เมื่อกดส่งออกภาพหน้าเดียว ให้ตรวจเฉพาะหน้านั้น; เมื่อส่งออกไฟล์รวมเล่ม ให้ตรวจทุกหน้าที่อยู่ในไฟล์ หากพบคำเตือนความอ่านง่ายที่ยังไม่เคยรับทราบของงานฉบับนั้น หรือมีหน้าที่ตรวจไม่สำเร็จ ให้เปิดรายงานพร้อมปุ่ม `ส่งออกต่อ` และ `กลับไปแก้`; หากตรวจครบและไม่พบคำเตือนใหม่ ให้ส่งออกตามขั้นตอนเดิม ขณะสแกนทั้งเล่มให้แสดงความคืบหน้าและปุ่ม `ส่งออกต่อโดยไม่รอผลตรวจ` เมนูเครื่องมือยังเปิดรายงานทั้งเล่มได้ตามเดิม
4. กดรายการแล้วปิดรายงาน ไปยังหน้าที่เกี่ยวข้อง และเน้นจุดข้อความเพื่อให้แก้ได้ทันที การเน้นเป็นสถานะชั่วคราว ไม่เปลี่ยนงานหรือสถานะการตรวจทานเดิม
5. ตรวจใหม่ทุกครั้งที่เปิดรายงานหรือเริ่มส่งออก เพื่อสะท้อนการแก้ข้อความ ตำแหน่ง ขนาด และสีล่าสุด ผลตรวจไม่บันทึกเป็นข้อมูลโปรเจกต์ เมื่อผู้ใช้เลือก `กลับไปแก้` ให้ทิ้งคำสั่งส่งออกเดิม ผู้ใช้กดส่งออกอีกครั้งหลังแก้ หากเป็นคำเตือนชุดเดิมของงานฉบับเดิมที่ผู้ใช้เห็นและส่งออกต่อไปแล้ว ให้ส่งออกครั้งถัดไปโดยไม่เปิดรายงานซ้ำ แต่ยังสแกนใหม่; ถ้ามีคำเตือนใหม่หรือแก้หน้าแล้วจึงเปิดรายงานอีก ผล `ตรวจไม่ได้` ต้องแสดงคำเตือนในการส่งออกทุกครั้งจนกว่าจะตรวจได้จริง
6. รายงานยังคงแสดงข้อมูลเดิมทั้งหมด คำเตือนความอ่านง่ายไม่เพิ่มเงื่อนไขห้ามส่งออกหรือการยืนยันสถานะตรวจทานหน้า

## เกณฑ์การตรวจ

- ข้ามจุดที่ถูกลบหรือไม่มีข้อความ และใช้ขนาดหน้าจริง/กรอบ/การหมุน/การปรับฟอนต์ที่มีผลต่อการส่งออก
- **ล้นกรอบ:** ใช้ผลการตัดบรรทัดและวัดข้อความตามฟอนต์ที่โหลดแล้วด้วยชุดคำนวณเดียวกับตัวเรนเดอร์; แจ้งเมื่อ `fits` เป็นเท็จหรือขอบเขตตัวอักษรหลังจัดวางเกินพื้นที่วาดจริง เกณฑ์ต้องครอบคลุมการปรับกรอบด้วยมือและกรณีฟอนต์ขั้นต่ำแล้วก็ยังล้น
- **ตัวเล็ก:** เทียบขนาดตัวอักษรที่เรนเดอร์กับความกว้างหน้าจริงและ 75% ของ `getReadableMinimumFontSize` (ปัจจุบันคือ `max(14, round(pageWidth * 0.0225))` พิกเซล); แจ้งเมื่อขนาดต่ำกว่าเกณฑ์ 75% และแสดงค่าที่วัดได้กับค่าที่ใช้แจ้งเตือน จุดที่ผู้ใช้ตั้งให้เล็กโดยตั้งใจยังเป็นคำเตือน ไม่ถูกแก้อัตโนมัติ
- **สีกลืน:** ตรวจทุกสไตล์ รวมถึง `auto`, `manual`, และ `source_faithful` โดยใช้สีเติม เส้นขอบ ความทึบ และพื้นหลังจากสไตล์/การสุ่มตัวอย่างที่ใช้กับหน้าจริง ประเมินความต่างสีเฉพาะเมื่อมีข้อมูลพื้นหลังที่เชื่อถือได้ และคำนึงถึงเส้นขอบที่ช่วยให้อ่านได้ สำหรับภาพหลายสี ใช้ตัวอย่างหลายจุดบริเวณที่ข้อความวางและตัดสินจากส่วนที่อ่านยาก ไม่ใช้ค่าเฉลี่ยทั้งกรอบ แจ้งเมื่อพื้นที่ข้อความส่วนที่มีนัยสำคัญมีความต่างสีต่ำกว่า 3:1 และไม่เปลี่ยนสีที่ผู้ใช้เลือก เป้าหมายราว 4.5:1 ของระบบปรับสีอัตโนมัติยังคงเดิม ส่วนคำเตือนนี้เน้นกรณีอ่านยากชัดเจน เกณฑ์สัดส่วนตัวอย่างที่ถือว่า `มีนัยสำคัญ` ต้องอยู่ในโมดูลเดียวกับการตรวจและพิสูจน์ด้วย fixture ภาพเข้ม ภาพอ่อน ภาพผสม และข้อความมีเส้นขอบก่อนเปิดใช้
- ถ้าโหลดภาพ ฟอนต์ หรือข้อมูลพื้นหลังที่จำเป็นไม่ได้ ให้แสดง `ตรวจการจัดข้อความไม่ได้` หรือ `ตรวจสีไม่ได้` ตามส่วนที่ขาด พร้อมเหตุผลสำหรับจุดหรือหน้าที่กระทบ ห้ามนับเป็นผ่าน และห้ามขัดขวางการส่งออก
- ไม่ใช้ค่าความต่างสีของข้อความ UI มาแทนเกณฑ์ของภาพมังงะที่มีเส้นขอบและเอฟเฟกต์

## โครงสร้างและลำดับข้อมูล

เพิ่มตัวประเมินแบบอ่านอย่างเดียวที่รับข้อมูลหน้า จุดข้อความ ขนาดภาพ สไตล์ล่าสุด และพื้นหลังที่มีอยู่ คืนรายการผล `issue` พร้อมตัวระบุหน้าและจุดข้อความ โดยแยก `unavailable` จาก `pass` รายงานเรียกตัวประเมินเมื่อเปิด ทำงานทีละหน้าหรือเป็นชุดเล็กเพื่อจำกัดหน่วยความจำ มีสถานะกำลังตรวจและสรุปผลบางส่วนได้ แต่ไม่ประกาศว่า “ทุกหน้าพร้อม” จนตรวจเสร็จ ขณะสแกนเพื่อส่งออก ผู้ใช้ยกเลิกรอผลและส่งออกต่อได้; หน้าที่สแกนไม่จบแสดงเป็น `ยังไม่ได้ตรวจ` ไม่ใช่ผ่าน เมื่อส่วนใดตรวจไม่สำเร็จ ให้แสดงผลที่ตรวจได้พร้อมรายการ `ตรวจไม่ได้` และทางเลือกส่งออกต่อ การเปิดรายงานซ้ำยกเลิกผลรอบเก่าและเริ่มจากสถานะงานปัจจุบัน ผลสแกนที่ยกเลิกหรือมาช้าต้องไม่เปิดรายงานย้อนหลังหลังส่งออกไปแล้ว

สถานะการเห็นคำเตือนเป็นสถานะชั่วคราวของเวิร์กสเปซ แยกจาก `Confirmed page revision` และ review gate เดิม ใช้ตัวระบุหน้า ฉบับแก้ไขของหน้า และชนิด/จุดของคำเตือนเพื่อไม่เปิดรายงานซ้ำเมื่อส่งออกหลายรูปแบบจากงานที่ไม่ได้แก้ บันทึกการเห็นคำเตือนเฉพาะเมื่อผู้ใช้กด `ส่งออกต่อ` หลังรายงานที่สแกนเสร็จ เมนูรายงานไม่ต้องมีคำเตือนใหม่ก็เปิดดูได้เสมอ ผล `unavailable` และ `ยังไม่ได้ตรวจ` ไม่ถูกนับเป็นผลผ่านหรือคำเตือนที่เคยรับทราบ

การนำทางใช้รหัสจุดข้อความที่เสถียรตามข้อมูลหน้า เปลี่ยนหน้าแล้วรอให้เลเยอร์ข้อความแสดง ก่อนเลื่อนและเน้นจุดที่พบ ถ้าจุดนั้นถูกลบหรือเปลี่ยนระหว่างตรวจ ให้ไปที่หน้านั้นและแจ้งว่าหาจุดเดิมไม่พบ โดยไม่เลือกจุดอื่นแทน

## ข้อผิดพลาดและขอบเขต

- การตรวจล้มเหลวเฉพาะหน้าไม่ทำให้รายงานทั้งเล่มหาย แสดงหน้าที่ตรวจไม่สำเร็จและให้เปิดรายงานใหม่เพื่อลองอีกครั้ง
- ผลตรวจอาจเป็นคำเตือนเกินจริงบนภาพที่มีเอฟเฟกต์หรือพื้นหลังซับซ้อน จึงใช้คำว่า “ควรตรวจ” และให้คนดูภาพจริงก่อนแก้
- ไม่ส่งภาพไปบริการใหม่ ไม่เรียก Gemini เพื่อตรวจ และไม่แก้ข้อความ สี หรือกรอบโดยอัตโนมัติ
- คำเตือนความอ่านง่ายไม่เปลี่ยน review gate เดิมสำหรับงานคลีน/คำแปลที่ไม่แน่ใจ; คำว่า `ส่งออกต่อ` หมายถึงดำเนินตามขั้นตอนส่งออกเดิม รวมถึงการยืนยันหน้าที่ review gate เดิมกำหนด

## เกณฑ์ยอมรับและการทดสอบ

1. จุดข้อความที่ล้นและจุดที่ฟอนต์ต่ำกว่าเกณฑ์ปรากฏในรายงานพร้อมเหตุผล และหายจากรายงานหลังแก้แล้วเปิดตรวจใหม่หรือกดส่งออกใหม่
2. จุดสีที่มีหลักฐานว่ากลืนกับพื้นหลังถูกแจ้ง ทั้งสไตล์อัตโนมัติและสไตล์ที่ผู้ใช้ตั้งเอง; กรณีไม่มีหลักฐานแสดง `ตรวจสีไม่ได้`
3. กดรายการแล้วไปหน้าและเน้นจุดตรงตัว แม้มีหลายหน้าหรือจุดที่มีข้อความซ้ำกัน; ถ้าจุดหายให้แจ้งอย่างตรงไปตรงมา
4. รายงานเดิมยังแสดงสถานะแปล อักษรปน กรอบผิดปกติ และงานคลีน; เมื่อกดส่งออกแล้วพบคำเตือนใหม่หรือหน้าที่ตรวจไม่ได้ ผู้ใช้เลือกแก้หรือส่งออกต่อตามขั้นตอนเดิมได้ การส่งออกหน้าเดียวตรวจเฉพาะหน้านั้น การส่งออกไฟล์รวมตรวจเฉพาะหน้าที่รวมในไฟล์
5. ตรวจด้วย fixture ที่มีฟอนต์ไทย ข้อความหลายบรรทัด บอลลูนขนาดเล็ก ข้อความบนภาพเข้ม/อ่อน และเส้นขอบที่ช่วยให้อ่านได้ พร้อมทดสอบการยกเลิกรอบตรวจเก่าและข้อผิดพลาดเฉพาะหน้า
6. ขณะตรวจไฟล์รวม ผู้ใช้เห็นความคืบหน้าและส่งออกต่อโดยไม่รอได้ ผลที่ยังตรวจไม่จบไม่ถูกนับเป็นผ่าน; ผลตรวจที่มาช้าไม่เปิดรายงานย้อนหลัง; ผล `ตรวจไม่ได้` แจ้งอีกในครั้งถัดไปแม้หน้าเดิมไม่เปลี่ยน
