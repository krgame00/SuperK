## Changes (owned paths, file:line)

### `lib/translation/qualityReview.ts`
- `isReviewCurrent` (qualityReview.ts:115) now rejects any snapshot whose recorded `policyVersion` differs from the current `LANGUAGE_POLICY_VERSION` — the G02-bound `policyVersion` is now consumed, so policy changes invalidate approval evidence. Absence of the field (pre-versioning snapshots) stays governed by the exact source/text/target comparisons; present-but-old always fails.

### `hooks/useTranslation.ts` (lib/translation/qualityReviewClient.ts is unchanged — whole-book repair reuses the G02 chunked client as-is)
- New exported types `ReviewIssuePoint`/`PageReviewIssues`/`LegacyTargetPage`/`WholeBookRepairSummary` (useTranslation.ts:76-110). `ReviewIssuePoint.humanConfirmable` is false for every script failure and for every point without source evidence.
- `inspectLegacyTargets()` (useTranslation.ts:2391): lists restored translated pages that have active text but no recorded target identity — the one-time legacy confirmation queue. No requests, no rewrites.
- `confirmLegacyTarget(confirmedTarget?)` (useTranslation.ts:2401): assigns a `PageTargetIdentity` (default = next-job selector, i.e. Thai suggested) to exactly the untargeted translated pages; pages with a recorded target keep their own language; unsupported targets return 0 (fail closed); metadata-only — bumps `cacheRevision` for autosave, never touches text or reviews.
- `inspectReviewIssues()` (useTranslation.ts:2420): local, request-free per-point classification for every active point on every page — script failures (with offending characters, reported even when a saved snapshot says `accepted`/`dismissed`), unverified points (absent review metadata — legacy/manual points cannot escape —, stale snapshots via `isReviewCurrent(bubble, targetId)` which now also consumes policy + target identity, or unresolved `unavailable/needs_review` statuses), and `targetUnconfirmed` pages. This is the retained actionable review list.
- `confirmPointReview(pageUrl, pointIndex)` (useTranslation.ts:2466): explicit source-backed human confirmation when script passes but contextual AI verification is unavailable. Refuses script-blocked points (they can never be confirmed/dismissed/accepted past), refuses points without source text, and refuses unconfirmed pages. On success it binds an exact snapshot — raw `sourceText`/`reviewedText`/`targetId`/`policyVersion`/`sourceRevision` — so any later text or target change invalidates it.
- Whole-book repair (useTranslation.ts:2491-2651): `applyRepairEntries` + `repairWholeBook` + `cancelWholeBookRepair` with `bookRepairAbortRef`/`isRepairingBook` (useTranslation.ts:333-334). Per page: only locally script-blocked points participate (sent through `reviewTranslatedBubbles(..., repairContamination:true)` — the G02 bounded one-round client, chunked at 64, one logical repair round per page, no `/api/translate`, no retranslation); pages without a recorded target are skipped and reported (`skipped: [{..., reason:"target-unconfirmed"}]`) instead of guessed; unrelated points and unrelated pages are untouched; repaired points keep styles/geometry with `originalTranslation` retained as diagnostic. Cancellation (user `cancelWholeBookRepair` or unmount abort, useTranslation.ts:2296-2299) stops remaining pages while completed pages keep their repairs (`summary.cancelled`). A single `undoManager` entry ("แก้ตัวอักษรปนทั้งเล่ม") is pushed when any text changed: Undo restores the exact pre-repair text + review evidence per affected point, Redo re-applies the repaired state, and neither touches unrelated points or edits made after the repair. Mutual exclusion reuses `translationOperationLockRef` (translation/batch cannot run mid-repair and vice versa; concurrent call returns null).
- Hook return exposes `inspectLegacyTargets, confirmLegacyTarget, inspectReviewIssues, confirmPointReview, repairWholeBook, cancelWholeBookRepair, isRepairingBook` (useTranslation.ts:2783-2789).
