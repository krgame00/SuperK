## Changes (exact owned paths, file:line)

### `lib/translation/qualityReview.ts`
- `TranslationReview` gains optional evidence-identity fields `targetId`/`policyVersion` (qualityReview.ts:19-20,22) so every snapshot carries the exact target-policy identity and status.
- New `withReviewIdentity(review, targetLang, sourceRevision?)` (qualityReview.ts:41) binds `targetId` (resolved profile id) + `LANGUAGE_POLICY_VERSION` + the exact source revision into every snapshot.
- `parseQualityReviews(items, response, targetLang, sourceRevision?)` (qualityReview.ts:72): every returned snapshot (including unavailable defaults) is identity-bound (qualityReview.ts:78,94,103); an item whose `sourceText` is empty after trim can never be approved — its provider row is ignored and it stays `unavailable` (qualityReview.ts:81). Missing/duplicate/malformed IDs keep the previous no-approval behavior.
- `isReviewCurrent(bubble, targetId?, sourceRevision?)` (qualityReview.ts:108): now compares **exact raw** `sourceText`/`reviewedText` (no `.trim()`) — trimmed evidence can no longer silently approve raw content — and additionally rejects mismatched target identity or source revision when supplied. Single-arg calls (used by `lib/translationOverlay.ts`, not modified) keep working text-only.

### `lib/translation/qualityReviewClient.ts` (rewritten)
- All active (non-deleted) points get an explicit snapshot before any network: source-less/over-limit points get `unavailable` (guard-wrapped so contaminated text reports needs_review with the offending characters) (qualityReviewClient.ts:38-47). Manual points are no longer excluded — they are reviewed like any active point; deleted points still never participate and pass through by reference.
- Review requests are chunked by `MAX_REVIEW_ITEMS` (64) via `chunkItems` (qualityReviewClient.ts:21,73): dense pages no longer leave points >64 silently unreviewed; a failed chunk keeps its explicit unavailable snapshots; a per-chunk 50 s timeout and user cancellation keep the prior semantics (timeout/network → explicit unavailable and return; user abort → AbortError).
- One logical automatic repair round (`repairContamination`, qualityReviewClient.ts:81-118): targets are computed **locally** as points whose current raw text is script-blocked (qualityReviewClient.ts:86-88); only affected point IDs are sent, in a request tagged `mode:"repair"`, chunked when >64 (qualityReviewClient.ts:89). A repair applies only when the parsed row is `suggested` with a replacement that already survived the one-time `guardQualityReview` validation in `parseQualityReviews` (qualityReviewClient.ts:99-114): text (`t` and `translated`) is replaced, styles/geometry untouched, snapshot becomes `ok` with `originalTranslation` retained as diagnostic. Missing/duplicate/malformed repair rows, provider "ok" without a replacement, no-op suggestions, and contaminated repair suggestions never resolve the point (round-1 needs_review snapshot stands); a failed repair request stops the round (no loop). Clean editorial suggestions are never auto-applied — they remain `suggested` for explicit acceptance.
- New options `sourceRevision`, `repairContamination` (qualityReviewClient.ts:14-16).

### `hooks/useTranslation.ts`
- `reviewPage` now passes `sourceRevision:String(getPageRevision(pageUrl))` and `repairContamination:true` (hooks/useTranslation.ts:1053), binding snapshots to the page's source revision and enabling exactly one repair round per page/run in both the normal and the NSFW-slice workflow (same closure).
- The full original-image contamination retry no longer stacks with point repair: the enhanced-image retry triggers only on the genuinely distinct 0-bubble recognition failure (hooks/useTranslation.ts:1382-1394); the retry result is adopted only when the first pass had nothing to keep (hooks/useTranslation.ts:1450-1459). `countContaminatedBubbles`/`isThaiTargetLanguage` imports removed (hooks/useTranslation.ts:30-33) — contamination detection is now the policy-based local inspection used by the client/repair and `unresolvedScriptWarning` (unchanged) still reports unresolved point IDs/characters after repair.
- `src/app/api/translation-review/route.ts`: **unchanged** — it already rejects duplicate/unknown IDs (400/502), leaves missing IDs absent (client marks them unavailable), overrides contaminated provider approvals via `guardQualityReview`, and caps items at 64 (client-side chunking respects this). Its tests (qualityReviewRoute.test.ts) pass unmodified.

## Limitations / notes
- Manual points now participate in provider review (per brief: client "excludes manual and >64 points" is evidence loss to eliminate; spec: "Process all active points… Manual edits receive local checks even where automatic provider review is skipped"). Manual points without source text get explicit `unavailable` snapshots — they can no longer silently pass export review gating; human-confirmation UI to resolve them is G03's scope.
- Old saved projects with legacy trimmed snapshots will now evaluate as not-current under exact comparison and be flagged `stale`/needing review on inspection — the intended elimination of silent approvals; re-verification or G03's human confirmation resolves them.
- The repair round is one logical round per `reviewTranslatedBubbles` invocation (= one per page per translation/retry run). A user-initiated re-translation is a new run and may attempt one repair round again; there is no automatic looping.
- The repair request tags `mode:"repair"`; the route ignores the extra key (validation permits unknown fields), so no server change was required for this slice.
- No real provider calls, no server restarts, no commits/pushes were performed; unrelated dirty files (docs, translationOverlay, sourceTextSize*, S02 files) were not touched.
